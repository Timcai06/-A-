# DeepSeek 模型与代码深度审计报告

**审计日期：** 2026-05-12  
**审计范围：** `src/models/dynamic_short_term.py`、`src/scenarios/simulation.py`、`src/calibration/search.py`、`src/calibration/evaluation.py`、`src/calibration/parameter_space.py`、`src/calibration/settings.py`  
**审计焦点：** 模型数学正确性、代码质量、校准严谨性、短期/长期一致性、数值稳定性、参数可辨识性

## 一、总体模型质量评价

模型代码整体质量**中上**。工程结构清晰，模块拆分合理，类型注解完整，随机种子固定保证了可复现性。模型的数学骨架（递推方程、ramp 函数、弹性插值）逻辑正确，没有发现符号错误或量纲混乱。

但存在若干**结构性隐患**——它们不影响当前 RMSE，但在严格建模评审下会削弱模型的可信度。这些隐患集中在三个区域：校准参数的可辨识性、长期模块级硬编码常数、以及短期/长期模型之间的机制继承关系。

## 二、核心递推方程审计

### 2.1 短期模型价格方程（第 249-257 行）

```
target_price = base_price
    + shortage_pressure          # 剩余物理缺口 → 价格
    + blockade_risk_premium      # 封锁事件风险溢价
    + uncertainty_premium        # 不确定性渐近溢价
    + panic_premium              # 恐慌因子 × 价格乘数
    - buffer_discount            # 缓冲确认折价
    - relief_discount            # 预期修复折价
```

**审计判断：方程逻辑完整，符号方向正确。** 正项（溢价）加到基准价上，负项（折价）从基准价减去。各分项量级互不矛盾。

**但存在一个数学结构性问题：** `shortage_pressure` 公式将 `pressure_scale` 与 `1/|elasticity|` 相乘。当 `elasticity` 从 -0.05 逐渐过渡到 -0.18（长期弹性）时，`1/|elasticity|` 从 20 降到约 5.6。这意味着同样的剩余缺口在后期产生的 `shortage_pressure` 会自动缩小——不是因为缺口变小了，而是因为弹性分母变大了。

这个设计在方向上是合理的（长期弹性更大→需求对价格更敏感→同样缺口的价格压力更小），但 `pressure_scale ≈ 0.028` 与 `1/|elasticity|` 的乘积效应使得 `shortage_pressure` 的量级主要被 `pressure_scale` 决定——弹性从 -0.05 变到 -0.18 只改变约 3.6 倍，而 `pressure_scale` 从 1.0 变到 0.028 改变了约 36 倍。**`pressure_scale` 是主导变量，弹性插值是配角。** 这一点在论文中应诚实说明。

### 2.2 价格平滑机制（第 259-261 行）

```python
simulated_price = previous_price + adjustment_speed * (target_price - previous_price)
simulated_price += 2.5 * (fear_excess - previous_fear_excess)
simulated_price = clip(simulated_price, base_price * 0.75, 180.0)
```

**第 260 行存在问题：恐慌变化被双重计入。** `fear_excess` 已经通过 `panic_premium` 进入了 `target_price`（第 246 行），再通过 `adjustment_speed` 平滑传导到价格。第 260 行额外叠加 `2.5 × Δfear` 动量项，相当于恐慌变化被计入了两次：一次通过 `panic_premium → target_price → adjustment_speed`，一次直接加到价格上。

这个设计在经验上可能有助于改善拟合（恐慌快速消退时价格加速回落），但缺乏独立的经济学论证。`FEAR_CHANGE_MOMENTUM = 2.5` 的来源应被解释——它是校准出来的，还是基于行为假设？

### 2.3 blockade_risk_premium 的函数形式（第 238-244 行）

```python
blockade_risk_premium = base_price * risk_weight
    * (supply_interruption / base_demand)
    * (1 - exp(-day/7))
    * exp(-0.004 * day)
```

双指数折衷形式：`1-e^{-t/7}` 负责前期快速积累，`e^{-0.004t}` 负责长期缓慢衰减。t=46 天时积累因子约 0.9986（饱和），衰减因子约 0.832；t=180 天时衰减因子约 0.487。

**衰减速度 `0.004` 是硬编码的**，未被纳入校准参数空间。如果开放此参数，模型可能找到不同最优解。当前论文通过反驳性检验（不确定性减半/强制衰减）部分弥补，但 `blockade_risk_premium` 的衰减参数仍是隐藏常数。

## 三、校准过程审计

### 3.1 三阶段校准管线的合理性

```
阶段 A: 36000 组随机搜索（离散格点采样）
    ↓
阶段 B: differential_evolution 连续优化（35 代，种群 7）
    ↓
阶段 C: 800 组局部扰动稳健性复核
    ↓
阶段 D: 60000 组拟合质量精修（scale=0.018→0.035→0.065）
```

**审计判断：管线设计合理。** 但有以下问题：

**问题一：阶段 A 的探索覆盖率极低。** `physical_grid`（6参数×3-5取值）和 `behavior_grid`（11参数×3-6取值）的组合空间远超 36000。随机采样只覆盖了可能空间的一小部分。

**问题二：differential_evolution 配置偏保守。** `popsize=7` 对 21 维空间偏小（经验法则建议至少 10-15 倍维度）。`tol=0.002` 对综合得分 ~6.64 来说很紧（0.03%），但目标函数非凸，可能过早收敛。

**问题三：多目标校准权重是隐藏超参数。** `evaluate_simulation` 中综合得分的各项权重（0.20/0.25/0.15/0.12/0.12/0.18/0.18）加上 `excellence_penalty`（0.15/0.15/0.15/0.08/0.10），共 12 个主观权重。这些权重的选取依据未被报告，也未做权重敏感性分析。

### 3.2 参数可辨识性评估

| 参数 | 可辨识性 | 依据 |
|------|:---:|------|
| `pressure_scale` | **高** | 与 RMSE 强相关，压力测试已证实 |
| `risk_weight` | **高** | 消融实验显示移除后 RMSE 剧烈恶化 |
| `uncertainty_floor` | 中高 | 与长期价格强相关，但短期窗口内与 `risk_weight` 存在共线性风险 |
| `inventory_response` | 中 | 库存缓冲量受 `inventory_daily_cap` 和 `inventory_remaining` 双重约束 |
| `adjustment_speed` | 中 | 影响路径平滑度而非水平，与其他参数交互弱 |
| `buffer_relief_strength` | **低** | 只有缺口闭合后才激活，46 天窗口内数据点极少 |
| `relief_discount_strength` | **低** | 仅在 35-46 天后激活，有效数据点约 10 个 |
| `relief_start_day / peak_day / decay_days` | **极低** | 三参数共同定义脉冲形状，脉冲仅覆盖约 20 个交易日 |

**核心问题：`buffer_relief` 和 `relief_discount` 两组参数在 46 天窗口内的可辨识性极低。** 它们描述"缺口闭合后市场情绪修复"的行为，但 46 天窗口中缺口是否闭合、何时闭合都不确定。缺少参数不确定性量化。

## 四、短期/长期模型一致性审计

### 4.1 机制继承关系

| 机制 | 短期 | 长期 | 一致性 |
|------|:---:|:---:|:---:|
| ramp 函数 | ✅ | ✅ | 相同 |
| 弹性插值 | ✅ | ✅ | 相同 |
| 价格调整需求 | ✅ | ✅ | 相同 |
| 库存缓冲 | ✅ | ✅ | 相同（库存初始值来自短期终点） |
| SPR 释放 | 固定 ramp | **自适应 taper** | 不同 |
| 恐慌因子 | ✅ | ✅ | 相同 |
| shortage_pressure | ✅ | ✅ | 相同 |
| blockade_risk_premium | ✅ | ✅ | 衰减速度硬编码——180天是否仍合适？ |
| uncertainty_premium | 单一公式 | **拆分为 shock+regime** | 不同 |
| 折价项 | buffer + relief | buffer + relief + **oversupply** | 长期多了 oversupply |

**三处关键差异需在论文中明确说明：**

**差异一：SPR 释放机制。** 短期用固定 ramp，长期用自适应 taper。同一参数 `spr_max_release` 在两个模型中有不同含义。短期 46 天窗口内 SPR 尚未到需收缩的时间尺度，固定 ramp 近似足够。

**差异二：不确定性溢价结构。** 短期用单一公式 `base × floor × (1-e^{-t/18})`；长期拆分为冲击不确定性（45天后衰减）和制度风险（依赖未解决物理压力，60天后衰减至 40% 底座）。`uncertainty_floor=0.247` 在两个模型中的**数值含义不同**。前 46 天两个公式的数值是否一致？需做对齐检查。

**差异三：oversupply_discount 仅存在于长期模型。** 短期假设 46 天内供给不可能超过需求（合理），但应在模型描述中指出此假设。

### 4.2 长期模块级常数的"隐藏参数"问题

`simulation.py` 第 17-39 行定义了 20 个模块级常数：

```python
GAP_CLOSURE_SHARE = 0.005
SPR_PRICE_STRESS_START_RATIO = 1.03
SPR_PRICE_STRESS_WIDTH = 0.25
SPR_MIN_POLICY_SHARE = 0.08
SPR_PRICE_POLICY_SHARE = 0.16
SPR_TAPER_START_DAY = 75
SPR_TAPER_FLOOR = 0.25
SPR_TAPER_DECAY_DAYS = 45
UNCERTAINTY_BUILDUP_DAYS = 18
SHOCK_UNCERTAINTY_SHARE = 0.45
SHOCK_DECAY_START_DAY = 45
SHOCK_DECAY_DAYS = 70
REGIME_RISK_SHARE = 0.90
REGIME_BASE_SHARE = 0.20
REGIME_STRESS_SHARE = 0.80
REGIME_CONFIDENCE_DECAY_START_DAY = 60
REGIME_CONFIDENCE_DECAY_FLOOR = 0.40
REGIME_CONFIDENCE_DECAY_DAYS = 120
PANIC_PRICE_MULTIPLIER = 0.45
FEAR_CHANGE_MOMENTUM = 2.5
OVERSUPPLY_REVERSION_SCALE = 1.35
```

**这是整个模型质量审计中最严重的问题。** 这 20 个常数：

1. **未被纳入校准参数空间**——未接受系统性搜索或敏感性分析。
2. **缺乏来源说明**——注释只说"intentionally kept at module level"，未解释取值依据。
3. **存在任意的相变阈值**——如 `SPR_TAPER_START_DAY=75`，为什么是 75 而非 60 或 90？
4. **相当于增加了 20 个隐藏参数**——加上 21 个校准参数，模型实际参数远超声明数量。

**推荐处理：**
- **P0**：将 `OVERSUPPLY_REVERSION_SCALE` 和 `REGIME_CONFIDENCE_DECAY_FLOOR` 纳入敏感性分析。
- **P1**：为每个常数补充取值依据注释。
- **P2**：将 `SPR_TAPER_START_DAY`、`REGIME_CONFIDENCE_DECAY_DAYS`、`OVERSUPPLY_REVERSION_SCALE` 暴露为可配置参数。

## 五、数值稳定性与边界处理

### 5.1 已做好的地方

| 位置 | 处理方式 | 评价 |
|------|---------|------|
| 弹性分母 | `max(abs(elasticity), 0.01)` | 防除零 |
| 价格下界 | `clip(..., base_price * 0.75, 180.0)` | 防负价格 |
| 价格上界 | `clip(..., ..., 180.0)` | 防数值爆炸 |
| 需求下界 | `max(..., base_demand * 0.70)` | 防需求坍缩 |
| 价格比下界 | `max(previous_price/base_price, 0.1)` | 防弹性计算异常 |
| ramp 除零 | `if ramp_days <= 0: return max_value` | 防除零 |
| SPR 需求驱动 | `max(gross_gap_before_spr + buffer, 0.0)` | 防负释放 |
| relief 除零 | `max(decay_days, 1)` / `max(ramp_days, 1)` | 防除零 |

### 5.2 仍存在的隐患

**隐患一：`panic_premium` 无 `fear_initial` 非负约束。** `fear_excess` 来自 `fear_initial × exp(-decay×day)`，若 `fear_initial < 0` 则恐慌溢价为负——虽然当前参数空间设定为正，但 `PhysicalAssumptions` 未强制约束。

**隐患二：`oversupply_discount` 量级验证。** 中性第 180 天过剩 50 万桶/日，弹性 ≈ -0.18：

```
折价 = 75 × 0.028 × 1.35 × (50/10000) / 0.18 = 0.08 美元/桶
```

与实际输出的 0.06 美元/桶接近，但 50 万桶/日持续过剩在 180 天尺度上的价格压力应远超 0.06 美元。**`OVERSUPPLY_REVERSION_SCALE=1.35` 可能保守过度。**

## 六、代码结构问题

**问题一：`perturb_fit_refinement_parameters` 的分段 scale 逻辑。**

```python
if sample_id < 20000:    scale = 0.018
elif sample_id < 45000:  scale = 0.035
else:                    scale = 0.065
```

三段式扰动幅度的设计意图是"小步精修→中步探索→大步防局部极小"，但 20000/45000 的分界点无依据。建议改为连续递增函数。

**问题二：`select_initial_behavior` 仅搜索 864 组合。** 阶段 3 入口很快被阶段 4 覆盖，建议标注"初始筛选 / 非最终最优"。

## 九、最终判断

模型数学骨架正确，无符号错误或逻辑矛盾。递推结构（物理缺口 → 价格压力 → 风险溢价 → 缓冲折价 → 平滑价格）形成内部自洽的解释框架。

参数体系存在结构性脆弱：21 个声明校准参数 + 20 个未声明模块级常数 = 实际自由度远大于论文呈现。最有效的加固措施是**将最重要的模块级常数（`OVERSUPPLY_REVERSION_SCALE`、`REGIME_CONFIDENCE_DECAY_FLOOR`、`SPR_TAPER_START_DAY`）暴露出来，接受与校准参数同等的敏感性检验，并在论文中报告 ±50% 扰动下的价格变化。**
