## 二、敏感性分析扩展质量审计

### 2.1 新增覆盖参数的表现

从敏感性结果（`output/sensitivity/敏感性分析结果.csv`）提取：

| 参数 | 重要性排名 | 综合敏感度 | 第180天波动范围（美元） | 评价 |
|------|:---:|:---:|:---:|------|
| REGIME_RISK_SHARE（制度风险占比） | 3 | 6.41 | 92.43 → 95.12（+2.69） | 高敏感，合理 |
| REGIME_CONFIDENCE_DECAY_FLOOR（信心底座） | 9 | 2.54 | 91.33 → 93.59（2.26） | 中敏感，对长期路径有实质影响 |
| SHOCK_UNCERTAINTY_SHARE（冲击占比） | 10 | 1.66 | 91.74 → 93.14（1.40） | 中低敏感 |
| OVERSUPPLY_REVERSION_SCALE（过剩回归） | 12 | 0.12 | 92.38 → 92.45（0.07） | **极低敏感** |
| SPR_TAPER_START_DAY（SPR收缩起点） | 14 | 0.00 | 几乎无影响 | **几乎无关** |

### 2.2 两个值得注意的信号

**信号一：`OVERSUPPLY_REVERSION_SCALE` 扰动 0.8→2.2 只导致第 180 天价格波动 0.07 美元。** 这证实了上一轮审计的判断——过剩供给折价机制在当前参数组合下影响极弱。但这不一定需要"修复"，因为：

- 悲观情景（缺口 598 万桶/日）无过剩，此参数不激活
- 乐观情景过剩 50 万桶/日，折价仍只有 0.05-0.09 美元
- 中性情景过剩 50 万桶/日，折价约 0.06 美元

**这反而可以成为论文的一个诚实论据：** "在 50 万桶/日的轻度过剩下，即使将过剩回归强度调高到 2.2，长期价格也几乎不变；只有当供给大幅超过需求时该机制才会显著起作用。当前三情景均未达到触发强过剩折价的供需状态，说明模型的价格回落主要来自风险溢价的自然衰减而非过剩折价。"

**信号二：`SPR_TAPER_START_DAY` 从 60 天扰动到 105 天对第 180 天价格几乎无影响。** 这说明 SPR 在 60 天后已经主要由需求驱动（`adaptive_spr_release` 中的 `demand_based_release`），时间驱动的 taper 只是配角。这其实是一个好消息——SPR 机制确实是自适应的，不是被拐点开关硬控的。

## 三、仍未解决的结构性问题

### 3.1 `FEAR_CHANGE_MOMENTUM` 双重计入（R4）

**状态：未修改，但已文档化。**

```python
# dynamic_short_term.py:260
simulated_price += 2.5 * (fear_excess - previous_fear_excess)

# simulation.py:347
simulated_price += FEAR_CHANGE_MOMENTUM * (fear_excess - previous_fear_excess)
```

`MechanismConstantNote` 中对此的描述是：

> "作为事件冲击吸收速度项，只影响恐慌变化率；论文中应表述为辅助动量审计点。"

这个处理方式可以接受——它承认了这个参数的特殊性并建议在论文中谨慎表述。上一轮审计建议"去掉直接叠加，仅依赖 panic_premium 通道"，但保留也有保留的理由：恐慌快速消退时，市场可能不只是通过目标价平滑下调，还会有一次性的情绪修复跳变。关键是论文中要把这个双重通道说清楚，不要让它看起来像无意的代码冗余。

**当前评价：可接受，但论文中必须解释。**

### 3.2 `blockade_risk_premium` 衰减速度硬编码（R6）

**状态：未修改。**

```python
# dynamic_short_term.py:243
* np.exp(-0.004 * day_index)

# simulation.py:320 (同样)
* np.exp(-0.004 * day_index)
```

`0.004` 既不在校准参数列表中，也不在敏感性参数列表中。它的影响是：t=180 天时封锁风险溢价衰减到初始值的 `e^{-0.72} ≈ 0.487`。如果这个衰减速度改变 50%（±0.002），长期价格会有多大变化？当前未能量化。

**建议：** 将 `blockade_risk_premium` 的衰减速度（当前硬编码 0.004）作为第 16 个参数纳入敏感性分析。这是少数几个仍未暴露的"隐藏常数"中影响最大的。

### 3.3 多目标校准权重敏感性（R3）

**状态：仍未报告。**

12 个主观权重（`evaluate_simulation` 中 8 个 + `excellence_penalty` 中 5 个）的选取依据仍未说明，也未经敏感性检验。不过这一点的优先级已经低于前面两项——15 参数敏感性 + 5 个机制常数文档化已经显著提升了模型透明度。

## 四、代码结构质量更新

### 4.1 新模块拆分评价

`scenarios/` 包现在包含：

```
scenarios/
├── __init__.py
├── parameters.py      # 参数构建
├── reporting.py       # 报告和图
├── scenario_forecast.py  # 主入口（100行）
├── settings.py        # 路径和常量
└── simulation.py      # 核心模拟逻辑（380行）
```

**评价：拆分合理。** `simulation.py` 仍是最大的文件（380 行），但包含了核心模拟逻辑、`MechanismConstantNote`、自适应 SPR、不确定性拆分和过剩折价，职责集中。入口文件缩减到 ~100 行，只做组装和调度。

### 4.2 `MechanismConstantNote` 设计评价

```python
@dataclass(frozen=True)
class MechanismConstantNote:
    name: str
    value: float
    role: str
    basis: str
    audit_status: str
```

**这是个好设计。** `frozen=True` 防止误改，`audit_status` 字段区分了"已纳入敏感性分析"和"暂作为机制设定"两类常数。建议后续将所有 20 个模块级常数都纳入这个结构，不只是当前 5 个。

## 七、当前建议（更新版）

### 建议立即处理（P0）

无。上一轮的 P0 问题（模块常数文档化和敏感性覆盖）已基本解决。

### 建议论文定稿前处理（P1）

1. **将 `blockade_risk_premium` 的衰减速度 0.004 纳入敏感性**：这是当前最大的仍未暴露的隐藏常数。将衰减速度扰动为 [0.002, 0.004, 0.006, 0.008]，观察第 180 天价格变化。
2. **将 `FEAR_CHANGE_MOMENTUM` 的双重计入机制在论文中明确说明**：一段话解释为什么恐慌变化既通过目标价传导又通过动量叠加——写出经济学理由，不留代码痕迹式的疑点。
3. **利用 `OVERSUPPLY_REVERSION_SCALE` 低敏感性作为论文诚实论据**：主动声明"过剩折价在轻度过剩下影响极微，模型的价格回归主要来自风险溢价衰减而非过剩折价机制"。

### 建议后续增强（P2）

4. 将剩余 15 个模块级常数也纳入 `MechanismConstantNote` 结构，形成完整的参数溯源表。
5. 补充 `blockade_risk_premium` 衰减速度的敏感性。
6. 短期/长期不确定性公式前 46 天数值对齐检查。
