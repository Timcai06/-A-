# 评委视角质疑与防御矩阵

本文档站在严格数学建模评委视角，对当前总论文和模型体系进行主动审查。它不是论文正文，而是后续修改论文、模型和附录时的施工清单。

当前总判断：

- 短期模型已经具备主模型资格，但必须继续控制“参数过多、机制项像拟合补丁”的质疑。
- 长期模型只能定位为 60--180 天条件情景预测，不能包装成已被真实未来数据验证的拟合模型。
- 论文素材充足，但需要继续强化“一个核心问题、一条证据链、多个防御检验”的叙事，而不是堆阶段成果。
- R 语言和 C++ 不建议进入当前主线。R 可作为后续计量审计补强，C++ 多智能体只保留为早期设想，不作为最终论文卖点。

## 0.1 新独立专家报告处理状态

`独立专家评审报告_20260512_模型诊断专家.md` 提出了更集中、更尖锐的长期模型质疑。当前已用 `src.analysis.expert_challenge_audit` 生成可复现审计，输出位置：

| 产物 | 作用 |
|---|---|
| `output/reports/专家质疑一致性审计报告.md` | 专家质疑回应与模型一致性审计报告 |
| `output/qa/长期模型一致性审计.csv` | 第 60/90/120/180 天供需、SPR、过剩和溢价明细 |
| `output/qa/专家质疑反驳性检验.csv` | 不确定性衰减、强过剩折价、SPR 反馈等反事实检验 |
| `output/qa/短期pressure_scale敏感性.csv` | `pressure_scale` 扰动和绝对值压力传导检验 |

当前审计结论：

- 专家报告中“中性第 180 天仍固定满额释放 670 万桶 SPR、形成 500--600 万桶过剩”的判断已经不符合当前代码。当前中性第 180 天 SPR 实际释放约 211.85 万桶/日，供给过剩约 100 万桶/日。
- 但专家报告指出的长期模型核心风险仍然成立：当前模型还不是完整一般均衡模型，供给过剩时价格向战前价格回归的内生机制偏弱。
- 不确定性溢价减半或强制随时间衰减会显著压低长期价格，说明长期结论对制度风险项敏感。
- `pressure_scale=1.0` 会使短期 RMSE 恶化到约 26.55，说明它不能解释为题面弹性的直接替代，而应明确写成行为价格传导参数。

## 3. 短期模型专项质疑

### 3.1 当前强项

短期模型的优势在于证据链比较完整：

- 与朴素上一日基准、三日均值、漂移随机游走、滚动 ARIMA 做了对比。
- 已明确预测步长：不是普通 T+1 交易预测，而是条件机制递推。
- 有曲线平移检验和拐点局部检验，用于防止“马后炮曲线”质疑。
- 有机制消融，能说明 SPR、需求收缩、风险溢价、修复折价不是纯装饰。
- 有过拟合压力测试和硬编码审计，能回答“冯·诺依曼大象”和“120 美元硬上限”质疑。

### 3.2 当前最危险的问题

短期模型最危险的不是 RMSE，而是解释 pressure_scale、风险溢价和折价项的学术合法性。

评委最可能抓住的问题是：

> 你是不是表面遵守题面 -0.05 弹性，实际用一个价格传导系数把压力缩小了？

建议论文采用以下防御逻辑：

1. 传统供需基准模型严格使用题面短期弹性，目的是得到无缓冲反事实上界。
2. 综合机制递推模型不是再次计算静态均衡价格，而是刻画期货市场在政策缓冲、库存、绕道、需求收缩和预期修复共同作用下，对剩余缺口的价格传导。
3. 因此，pressure_scale 的语义是“剩余缺口向期货目标价格的传导比例”，不是需求价格弹性。
4. 该参数必须接受消融、扰动和历史边界检验，不能单独作为黑箱调参使用。

建议补强动作：

- 新增一张“参数分类表”：题面给定、附件统计、外部审计、校准参数、情景参数。
- 在论文公式下明确区分 \(\varepsilon\) 与价格传导系数。
- 在附录列出 pressure_scale 的取值、作用、扰动范围和敏感性。

## 4. 长期模型专项质疑

### 4.1 当前强项

长期模型已经从最危险的固定释放和永久平台里走出来了，当前已有：

- 自适应 SPR 释放机制。
- 长期需求弹性。
- 供给恢复、绕道运输和库存耗尽风险。
- 三情景路径。
- 单因素敏感性分析。
- 2000 次蒙特卡洛情景树。
- EIA 官方数据审计。

### 4.2 当前最危险的问题

长期模型最大的风险是：

> 评委可能把三情景中心线当成真实预测，然后质疑中性路径太平滑、太确定、缺少未来验证。

这个问题不能靠继续压低误差解决，因为长期没有未来真实观测。正确处理是改变论文表达重心：

- 不说“长期模型拟合效果好”。
- 说“长期模型给出条件中心路径、风险区间和尾部概率”。
- 三条中心线只是故事骨架，蒙特卡洛扇形区间才是可信度表达。

建议补强动作：

1. 把 `monte_carlo_price_fan.png` 的地位提高，作为长期结果主图之一。
2. 在长期结果表后加一段“如何阅读长期曲线”。
3. 加一个“长期模型不能验证未来真实价格，因此评价标准不是 RMSE，而是机制一致性、参数边界、敏感性和尾部风险”。
4. 在附录放长期关键变量路径，例如实际 SPR 释放、剩余缺口、库存剩余、风险溢价。

## 5. 论文写作专项质疑

当前论文素材已经足够，但评委读论文时不希望看到“阶段 1、阶段 2、阶段 3”的开发流水账，而希望看到完整论证：

```mermaid
flowchart LR
    A["题面冲突：巨大缺口 vs 110-120 平台"] --> B["传统低弹性供需模型给出反事实上界"]
    B --> C["说明静态模型高估现实价格"]
    C --> D["综合机制递推模型解释短期真实路径"]
    D --> E["基准、滞后、消融、过拟合、硬编码审计"]
    E --> F["60-180 天条件情景预测"]
    F --> G["敏感性和蒙特卡洛刻画尾部风险"]
    G --> H["结论：平台来自政策缓冲、需求调整和风险再定价共同作用"]
```

下一轮论文精修应优先做三件事：

1. 每一节开头都回答“这一节解决哪个评委质疑”。
2. 所有图表标题从“展示结果”改成“支持某个论点”。
3. 结论部分不要只复述数字，要回到赛题问题：为什么没有冲到 200 以上、持续封锁下哪里最危险、政策变量能缓冲什么不能缓冲什么。

## 6. R 语言与 C++ 的最终处理口径

### 6.1 R 语言

最终处理：

- 不进入当前主线。
- 不重写现有 Python 模型。
- 作为可选计量审计工具保留在改进方向。

理由：

- 当前任务核心是事件机制递推、情景预测和论文交付，不是纯时间序列建模竞赛。
- Python 已经形成从 CSV 到图表、报告、PDF、DOCX 的完整复现链。
- R 的优势在正式计量生态，适合后续补 GARCH、VAR、Granger、稳健标准误和高质量统计表。

论文口径：

> 本文主模型采用 Python 实现，原因是需要统一完成数据清洗、机制递推、情景仿真、可视化和论文构建。R 语言适合进一步开展 GARCH、VAR、Granger 等计量审计，但不是当前机制递推模型的必要前提。

### 6.2 C++

最终处理：

- 不进入当前主线。
- 不作为论文卖点。
- 只保留在历史材料中，作为早期多智能体设想。

理由：

- 当前数据规模很小，不需要 C++ 性能优势。
- 多智能体模型若没有个体级真实数据，很容易变成更难解释的参数系统。
- 赛题更重视可解释、可复算、能写清楚的机制模型。

论文口径：

> 本文不采用 C++ 多智能体仿真作为主模型。原因是附件数据主要为日度价格序列，缺少微观交易者、油轮、库存主体的个体级数据。强行构建多智能体系统会增加不可识别参数，反而削弱模型可解释性。本文选择 Python 机制递推模型，以保证数据来源、参数含义和结果复现更加透明。

## 8. 当前结论

从评委视角看，当前项目已经有比较强的短期模型和完整的论文雏形，但不能再用“继续加复杂模型”的方式提升质量。下一步最有效的提升路线是：

1. 把短期模型的参数来源和机制合法性讲得更清楚。
